# 动态指导助手

当前版本：**v2.28**（发布标签：`v2.28`）

把完整剧情大纲、物品规则和秘密写在角色世界书的条目里，用 `## 阶段名` 分段。动态指导助手会关闭来源条目，并在同一本世界书里维护一个「（动态指导）」镜像条目：位置、顺序、关键词等设置全部跟随原条目，内容只有当前阶段、当前有效的附加内容和常驻提示——相当于暂时让其余内容不被 AI 看到。可以同时添加好几个条目，各自独立推进、各自显示在自己的位置；想看回全文时点「解绑」就会删掉镜像、重新打开条目。阶段结构直接保存在世界书正文中；绑定列表记在角色变量里，每条绑定的进度只记在当前聊天里，新聊天从第一段开始。

“划分阶段”有两种改法：点段落加标题，或者切到“编辑原文”直接改世界书正文。手机和电脑使用同一套操作，不再需要拖选文字或保存隐藏选区。

## 安装与开始使用

在 [v2.28 发布页](https://github.com/PlayerAlex/sillytavern-dynamic-guide/releases/tag/v2.28)下载导入文件：

- [离线版 JSON](https://github.com/PlayerAlex/sillytavern-dynamic-guide/releases/download/v2.28/dynamic-guide-offline-v2.28.json)：内置完整脚本，导入后运行不依赖远程脚本下载。
- [在线版 JSON](https://github.com/PlayerAlex/sillytavern-dynamic-guide/releases/download/v2.28/dynamic-guide-online-v2.28.json)：启动时加载固定版本的远程脚本。
- [标记隐藏 Regex](https://github.com/PlayerAlex/sillytavern-dynamic-guide/releases/download/v2.28/dynamic-guide-regex-marker-hide-v2.28.json)：可选配套——让 AI 回复末尾的完成标记完全不显示（只影响显示层，脚本仍会把它从存储里擦掉）。

1. 在酒馆助手中导入并启用“动态指导助手”脚本，或导入发布仓库的在线版 JSON。
2. 给角色绑定一个世界书，在其中新建“大纲”条目。可以直接使用下面的文本模板，也可以先写普通大纲，用空行分开段落。
3. 点击酒馆左下角魔法棒，打开“动态指导助手”。
4. 在「动态指导」页的「绑定世界书」卡里选择一个世界书，再选一个条目。这一行只有一个按钮，按状态变形：条目还没分阶段时它是「划分阶段」，分好了就变成「绑定」，已绑定则置灰显示「已绑定」。
5. 点「划分阶段」进编辑器。**「分段」视图里正文是连续铺开的原始正文，一开始整篇都标着「未分配」**——分段完全由你自己划：在正文上拖选一段文字，底部浮出分配栏，从「选择归属…」里挑「＋ 新阶段…」或「＋ 新附加…」（也可以直接选「常驻提示」「备注」，或选「未分配（不发送）」把文字退回去）。新建的分段名字默认取你选中文字的首行，紧接着弹出属性弹层，在那里改名称、填「什么时候进入下一段（AI 自己判断）」。点任意一条标题条都能再打开这个弹层；↑↓ 交换相邻两段。想直接改文字就切到「编辑原文」。
6. 点「保存」。脚本会保存正文、读回校验；条目已绑定时还会立刻按新正文同步镜像，进度按阶段名自动对上。
7. 回到「动态指导」页点「绑定」，条目立刻变成一张常驻小卡（条目名 + 世界书名 + 段数步进器：上一段 / 当前段 + 阶段名 + 进度条 / 下一段）。**再想改划分，点小卡步进器中间那块**——它就是「划分阶段」入口，进去会直接落在这一条当前的段上；不同小卡进去分的就是各自条目的段。小卡右上角的 × 会把条目重新打开并删掉它在当前聊天的进度（会先弹确认）。
8. 保存或导出带有该世界书的角色卡。阶段标题和规则就在条目正文中，会随条目一起分享；接收者启用脚本并添加这个条目即可使用。

“保存”只更新条目正文，进度按阶段名自动对上。修改阶段时若要保留当前聊天进度，用「保存」即可；要重置进度就在小卡上用 ← / → 手动拨回第一段。

## 在线加载

远程 `index.js` 会自行在左下角魔法棒菜单注册“动态指导助手”入口。酒馆助手脚本正文可以只写一行：

```js
import 'https://gcore.jsdelivr.net/gh/PlayerAlex/sillytavern-dynamic-guide@v2.28/index.js';
```

推荐直接导入[发布仓库](https://github.com/PlayerAlex/sillytavern-dynamic-guide)提供的在线版 JSON。固定标签地址不会随新版本发布而改变；升级时导入新版在线版 JSON，或替换地址中的版本号。当前项目版本、Git 标签及在线加载地址均使用 `v2.28`。

## v2.0 文本格式

标题单独占一行，标题下面的内容属于这个块，直到下一个标题为止。没有类型标记的标题就是剧情阶段，按正文中的顺序推进。

```text
## 雨夜初遇
完成：两人完成第一次正式交谈。
{{char}}第一次在雨夜遇见{{user}}。
暂时不要透露地下室的秘密。

## 地下室的声音
完成：{{user}}决定调查地下室。
夜深后，地下室会传来断续的敲击声。
{{char}}知道声音不正常，但仍不愿说明真相。

## 蚀月戒指 [附加]
从：地下室的声音
到：进入地下室
戒指能看见灵体。
副作用是佩戴者会逐渐分不清死人和活人。

## 进入地下室
完成：地下室事件结束。
两人正式进入地下室，现在可以逐步揭示地下室的秘密。

## 写作风格 [常驻]
保持阴冷克制的笔调，不代替{{user}}作决定。

## 作者备忘 [备注]
这一部分只供作者整理思路，不发送给 AI。
```

| 写法 | 作用 |
| --- | --- |
| `## 阶段名` | 一个剧情阶段，占一个主线进度位置。 |
| `完成：条件` | 由 AI 判断本次回复是否已满足条件，满足后自动推进。留空时按全局「自动推进」设置处理（默认手动点“下一段”）。 |
| `完成：自动` | 不预设具体条件，由 AI 自己判断这一阶段何时算充分展开。只影响这一个阶段，跨档位生效。 |
| `## 名称 [附加]` | 物品、地点规则、秘密等附加内容，不占主线进度。 |
| `从：阶段名` / `到：阶段名` | 附加内容的有效范围，开始和结束阶段都包含在内。 |
| `## 名称 [常驻]` | 在每个尚在进行的阶段中一起发送。全部阶段完成后也停止发送。 |
| `## 名称 [备注]` | 只保存在正文中，不发送给 AI。 |
| `合并到：阶段名` | 把这一块的内容并进指定阶段，和它一起发送，但自己不算一个新的进度位置。 |

`合并到：` 用来处理一个阶段里内容不连续的情况。比如“进入地下室”这个阶段中间插了一段别的内容，后面还有它自己的第二段文字，就给后面那段写一个标题，并在标题下一行写 `合并到：进入地下室`。两段文字会一起发给 AI，进度仍然只算“进入地下室”这一段。

```text
## 进入地下室
两人正式进入地下室。

## 地下室的岔路
合并到：进入地下室
岔路口的线索只在这一段出现。
```

完成条件最好写成明确发生的事件，例如“双方已经交换真实姓名”。脚本不调用额外的 AI API：它把条件交给当前回复模型，要求模型满足条件后附加隐藏完成标记，再据此推进。判断有偏差时可手动修正。

附加范围建议直接填写唯一的阶段名，也支持 `第2段`、`2` 等阶段序号。省略“从”时默认从它前面的剧情阶段开始；放在第一阶段前的附加内容默认归第一阶段。省略“到”时只在开始阶段有效。找不到开始阶段时回退到所在阶段，找不到结束阶段时回退到开始阶段；结束早于开始时只在开始阶段有效。管理页和编辑器会对这些情况给出提醒。

格式细节：

- 推荐始终使用 `## 名称`。解析器也接受 1～6 级 Markdown 标题和 `【名称】`；这些都是同级内容块，不表示嵌套。正文中的普通 Markdown 小标题也会开始一个新块。
- 第一个标题之前的文字不发送给 AI。每个阶段中可以有多个空行分隔的段落，它们仍属于同一阶段。
- 标题后的 `[附加]`、`[常驻]`、`[备注]` 决定内容类型；类型标记应放在整行末尾。
- `完成条件：` 与 `完成：` 等价。标签和值写在同一行最清楚；标签单独一行时，后续连续非空行会作为它的值，直到空行、另一标签或标题。
- 阶段名称建议保持唯一，便于附加范围引用和编辑后的进度定位。正文中的 `完成：`、`从：`、`到：` 等格式会被当作规则标签，不当作普通指导正文。
- 若要把标题或规则标签当作普通指导文字保留，在行首加一个反斜杠，例如 `\## 普通小标题`、`\【人物状态】`、`\完成：这句话只是正文`。这些行不会创建阶段或设置规则，发送给 AI 时会去掉转义用的反斜杠。

## 划分阶段编辑器

“划分阶段”里有三个视图，编辑的都是世界书条目本身的内容，随时可以来回切换：

- **看分段**：按空行把正文展示成可点击的段落，用来点选设置标题。
- **选区划分**：把正文铺成一段连续文字，用拖选或点选把文字分给各个分段。
- **编辑原文**：直接编辑条目正文的文本框，增删文字、调整顺序、自己写 `## 阶段名` 都行。切回“看分段”会重新按标题解析一次。

“选区划分”里的操作：

- **选分段**：顶部每个分段一枚彩色圆点 chip（阶段、附加、常驻提示、备注），点一下设为当前分段；`+ 阶段` / `+ 附加` 新建。
- **拖选**：在正文上按住拖出一段文字，松手后进入“已准备 N 段”；可以接着拖选更多段，再点“分配给「当前分段」”一次分完。触屏不好拖选时点“点选头尾”：点一下正文设开头，再点一下设结尾。
- **分配即重建**：分配、移除、删除分段会立刻按归属重写正文标题——阶段的顺序跟着它第一段文字的位置走，没分配的文字留在最前面（第一个标题之前，不会发给 AI，下次打开还能继续分配）。
- **点已上色的文字**：把它所在的分段设为当前分段并选中那一段；选区栏出现“移除选中段”，点了这段文字就回到未分配。
- **改名和条件**：在 chip 下方的设置区改名称、完成条件、附加的起止阶段。这类修改不触发重建，切视图或保存时才一次性写回，打字不会丢焦点。

“看分段”里的操作：

- **点段落**：在这一段前添加标题，选择剧情阶段、附加内容、常驻或备注。已有阶段中的段落也可以成为新阶段的开头。
- **把第一行变成标题**：当段落首行较短、看起来像标题时，可以勾选“这一段的第一行就是标题，把它变成标题行”；取消勾选则在原段落前插入新标题。
- **点已有标题**：修改名称、类型、完成条件；附加内容可以从下拉列表选择起止阶段。剧情阶段改名时，“从 / 到”中可解析到旧阶段名的引用会同步修改，包括带书名号或引号的旧写法；阶段序号引用保持不变。
- **上移 / 下移**：标题卡右侧的 ↑↓ 把这一块（标题、标签、正文）整体挪动一个位置。阶段顺序就是进度顺序；常驻块挪到所有阶段之前时，注入里排在当前阶段内容**之前**，写在阶段之间或最后则排在附加内容区——“常驻提示在上面还是下面”由它的位置决定。选区划分的重建会保留这个位置，常驻 chip 的设置区也有“排在阶段内容之前 / 之后”的开关。
- **删除标题**：移除该标题及其规则标签，正文并入前一个内容块。删除第一个标题后，留在第一个标题之前的文字不发送。
- **按空行自动分段**：仅在还没有标题时显示。每个空行隔开的块形成一段；首行符合短标题判断时将其变成标题，否则添加“第 N 段”标题。自动分段后仍需检查名称和完成条件。
- **并入已有阶段**：把这一段设成“并入已有阶段”，再选一个目标阶段，这一段文字就会和那个阶段一起发送，但不占新的进度位置。
- **保存**：把标题及规则标签写入世界书正文并读回校验。普通编辑会保留指导正文；选用首行作标题时会把该行转成标题，删除标题时也会整理多余空行。

改写大段正文、移动整个内容块这类操作，直接切到“编辑原文”改，或者在酒馆的世界书编辑器里改，再回管理页点击“刷新”检查结果。保存只写正文，绑定关系与聊天进度不受影响。

## 从 1.x 升级

### 已经使用旧文本模板

`【内容：名称】`、`什么时候出现：`、`告诉AI：`、`什么时候消失：` 等旧模板语法仍可解析。剧情阶段的“什么时候消失”会作为完成条件；`类型：重要物品` 等非主线类型会作为附加内容。

旧模板能被识别，不代表旧自然语言时机规则完全相同。v2.0 主线只按正文顺序推进，附加内容只按阶段范围启停：

- `《进入地下室》正在进行时`、`《进入地下室》结束后` 都只会提取书名号中的阶段名，不再区分“进行时”“结束后”的偏移；起止范围包含该阶段。
- `游戏开始时`、`上一段结束后`、`进入某地点时` 等句子不会被当作独立触发事件。用于附加范围且无法解析到阶段时，会提醒并按上述默认范围回退。
- 升级后应核对附加范围，推荐改写成明确的 `从：阶段名`、`到：阶段名`。阶段仍按顺序推进，不会依据“什么时候出现”跳转或等待事件。

### 曾经用选区高亮划分阶段

v1.3 系列的选区划分保存在条目扩展数据或正文末尾的 `DGA_LAYOUT_V1` 隐藏标记中。v2.0 起会识别可读取的旧划分，并在管理页提供“转换成新版格式”；这类条目在转换前暂停指导注入，需要先转换，才能继续使用、重新添加或进入新版编辑器。

1. 选择带有“旧版划分，需转换”提示的条目，点击“转换成新版格式”。
2. 转换会**直接改写世界书正文**：按旧阶段顺序生成 `## 阶段名` 与完成条件，把每个阶段能定位到的选区按原文顺序拼接；旧常驻选区变成 `[常驻]` 块。搬运文字中看起来像标题或规则标签的行会自动转义，避免被误识别为新阶段或规则，发送时还原原文。
3. 没有分配到阶段的原文汇总到末尾的“旧版没有分配的文字 [备注]”，不再发送。无法重新定位的旧选区不会还原成原阶段，检查时要特别留意备注和空阶段。
4. 转换会移除旧正文隐藏标记和条目中的 `extra.dynamicGuideAssistant` 数据。阶段颜色由新版按顺序分配，不保留旧版自定义颜色。
5. 打开“划分阶段”检查内容、完成条件与顺序，再点“保存并添加”或回管理页“重新添加”。重新添加后当前聊天从第一段开始；转换动作本身不会重置聊天进度。

新版不再使用或恢复角色变量、全局变量中的旧 `layouts` 备份，也不再把划分写回隐藏选区数据。若旧扩展数据和正文隐藏标记都已丢失，需要先在旧版恢复划分，或在新版直接重新添加标题。

## 进度与运行方式

- 阶段、附加范围、完成条件都在世界书正文里；角色变量 `$dynamicGuideAssistant.config` 保存绑定列表 `{ version: 2, bindings: [{ worldbookName, entryUid, entryName, boundAt, mirrorUid }] }`。
- 每条绑定的进度分别保存在聊天变量 `$dynamicGuideAssistant.state.bindings[绑定键]`。不同聊天独立，新聊天从第一段开始，“回到第一段”只影响当前聊天里这一条绑定。
- 兼容旧版数据：2.0 的单个绑定和扁平进度会在读取时自动迁移到第一个绑定名下并写回；1.x 进度中的 `mainIndex / mainName` 也仍能识别；≤2.4 的提示词注入残留会在第一次启动时自动清理。修改正文后优先按当前阶段名称定位，找不到同名阶段时按原序号限制到有效范围；重新添加始终重置为第一段。
- 添加时关闭来源条目并读回核实，避免完整大纲经世界书原生机制发送。来源条目之后被重新打开时，脚本会在下次同步时再次关闭。点「解绑」会重新打开条目、删掉它的镜像条目和在当前聊天的进度。
- 每条绑定在同一本世界书里维护一个「（动态指导）」镜像条目：克隆来源条目的全部设置——位置（角色定义前/后、按深度插入的深度与角色、示例消息等）、顺序、关键词、概率、递归开关——只把内容换成当前阶段的切片，所以指导就显示在来源条目原来的位置，和其他世界书条目的相对顺序不变。来源条目调整位置后，镜像会在下次同步时跟着挪。卡片里“现在发给 AI 的内容”会写出这条绑定的实际位置。
- 镜像内容始终跟随进度：页面打开、添加、上一段 / 下一段、完成标记推进和切换聊天后都会立刻同步镜像；生成事件里再同步兜底一次（swipe / 重新生成时换用推进前的阶段）。同步是幂等的：内容或位置有变化才写世界书，没有变化就不写。一条回复可以同时带多条绑定的完成标记，脚本按各自的阶段 id 分别推进，并在接口可用时从回复中移除标记。
- 自动推进后立即重新生成该条回复时，脚本会尝试仍使用推进前的阶段。管理页随时可以手动调整每条绑定的进度。
- 全部阶段完成后这条绑定不再显示任何指导（镜像会被移除），包括附加与常驻内容；可以点“上一段”或“回到第一段”恢复。
- 「自动推进」是全局三档设置（管理页顶部设置卡），对没有写 `完成：` 条件的阶段生效：**手动推进**（默认）只能手动点“下一段”；**标记判断**在镜像末尾附一段通用判断指令和隐藏标记，由正文 AI 自己决定时机，不额外花请求；**判断AI**在每条 AI 回复后用 `generateRaw` 静默判定，回答 YES 才推进，每条回复多花一次小请求。单个阶段写 `完成：自动` 可跨档位单独开启 AI 判断；判断AI判定期间如果进度已被标记或手动推进、或来了新回复，这次判定会被放弃。
- 判断AI可以使用动态指导助手自己管理的 API 预设：点左上角目录按钮进入「API」页，连接方式三选（酒馆主 API / 自定义 / 酒馆预设——分别走酒馆当前主接口、直连酒馆后端转发、酒馆连接管理器中的预设）。自定义时再选接口协议四选（兼容 OpenAI / OpenAI Responses / Claude Messages / Gemini Interactions），填写端点 URL、API Key、模型名（点「加载模型」由酒馆服务器代发拉取，新建预设不用先保存）、最大回复长度和温度，并可设置附加主体参数、排除主体参数、提示词后处理、附加请求标头等高级参数。完整预设只保存在当前浏览器的 `localStorage`；角色变量只记当前选中的预设名，因此 Key 不随角色卡导出。`localStorage` 是本机明文存储，使用共享设备时不要保存敏感 Key。
- 判断AI的提示词在独立的「判断AI提示词」页按段自定义（每段可选 system / user / assistant 角色，支持占位符 `{{stage}} {{prompt}} {{condition}} {{history}}`，可一键导入导出、恢复默认）。判断时**只看 AI 最新 1 段正文**（用户消息不发送，参考段数可在「动态指导」页调成 2 / 3 / 6 / 自定义）。「动态指导」页的「提取 / 排除规则」卡与数据库填表规则同一语义：发送前逐段过滤角色回复——提取规则只保留「开始边界~结束边界」之间的内容（含边界、取最后一处命中），排除规则删掉「开始边界~结束边界」区间（含边界、支持嵌套）；解析结论前也会对判断AI的输出再过滤一次（无命中时原样保留）。规则开始和结束边界都填上会自动保存生效，同卡的规则测试器可用当前规则直接试跑样例或最近一次真实输出；留空 = 不过滤。
- 目录抽屉里的「运行日志」页实时记录判断AI检查与结论、阶段推进、绑定变更、拉取模型等事件，支持等级筛选、复制与清空；日志只存内存（上限 500 条），不写变量、不上传。

当前版本采用线性阶段，不支持分支剧情图。自动推进依赖模型遵守完成标记，复杂条件可能需要手动调整。“只显示当前内容”仅控制镜像条目本次发送的指导，不会删除聊天历史中已经出现的信息。

### v2.1（2026-09-20）

- 每条绑定在管理页显示为一张卡片：条目名与来源世界书、第 N 段 · 共 M 段、上一段 / 下一段、折叠的“现在发给 AI 的内容”，以及“重新划分 / 回到第一段 / 移出”一排不常用操作。点“移出”会重新打开条目并删掉它在当前聊天的进度；条目被意外打开时卡片会警告并给出“立即关闭条目”。
- 管理页简化成“卡片列表 + 一个添加区”：两个下拉选世界书和条目，旁边就是“划分阶段”和“添加为指导条目”；空绑定时显示三步上手引导。编辑器里“保存并绑定”更名“保存并添加”；已添加的条目在编辑器里只提供“保存”，修改正文后进度按阶段名自动对上，不会被误归零。
- 2.0 的单个绑定配置和扁平聊天进度读取时自动迁移到多绑定结构并写回，无需手动操作。
- 措辞统一为“关闭 / 打开条目”“添加 / 移出”，与管理页实际行为一致。
